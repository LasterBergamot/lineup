# Container, fonts and Compose

The template is authored in Calibri/Calibri Light (proprietary). The container ships the libre metric-compatible substitutes (Carlito etc.) so the PDF layout matches the source `.docx`; without them LibreOffice substitutes a differently-sized font and the tab-stop/table layout drifts.

## Image and Compose

- `backend/Dockerfile`: two stages, both `python:3.14-slim` **pinned by digest** (Dependabot's docker ecosystem bumps tag + digest). *builder* installs the deps with the pinned `uv` image (`uv sync --frozen --no-dev`, bytecode-compiled); *runtime* adds `libreoffice-writer-nogui` (no GUI stack; fidelity verified by the e2e suite), `tini` as PID 1 (`ENTRYPOINT ["tini", "--"]`, reaps `soffice.bin` children, instant `docker stop`) and the fonts, then copies the venv in. uv is not in the final image, and neither is pip (`pip uninstall` in the runtime stage: the venv is already built, and pip's vendored urllib3/certifi/msgpack/setuptools were what Trivy flagged). The image runs 3.14 while dev tooling and CI stay on 3.13+ (`requires-python`); 3.15 is blocked until lxml, pydantic-core, httptools, markupsafe, pyyaml and uvloop ship 3.15 wheels (check with `uv sync --frozen --no-dev --no-build --python 3.15`). `.github/dependabot.yml` ignores `python` >= 3.15 for the same reason; remove that entry when the check passes. Runs as the non-root `app` user (uid 10001, owns `/app` so the default SQLite file can be written; `HOME=/home/app`). `HEALTHCHECK` polls `GET /health` (liveness only, so a DB outage doesn't restart the container) with the interpreter, since curl isn't installed. `PYTHONUNBUFFERED=1`. Image size went from ~1.16 GB to ~870 MB
- Fonts: `--no-install-recommends` is kept, so the metric-compatible font packages are installed explicitly — `fonts-crosextra-carlito` (Calibri/Calibri Light), `fonts-crosextra-caladea` (Cambria), `fonts-liberation2` (Arial/Times/Courier). `backend/docker/fontconfig/99-calibri-carlito.conf` (copied to `/etc/fonts/conf.d/`) forces Calibri → Carlito, and `fc-cache -f` refreshes the cache. These are what make the PDF match the source `.docx`.
- The Docker build context is `backend/` (`docker build -t lineup backend` in the Taskfile), so repo-root items (`.github/`, `.claude/`, `documentation/`, `frontend/`, `compose.yml`, `Taskfile.yml`) can never enter the image. `backend/.dockerignore` is a security control: the Dockerfile does `COPY . .`, so it must exclude `.env`/`.env.*` (`backend/.env` holds the Supabase credentials and now sits *inside* the context) and `*.db`, alongside tests, `*.md`, caches, `.git`. Add any new secret/local-state file to it. Because `tests/` is excluded the image ships without tests — that's why the e2e suite runs from the host against the running container, not inside the image.
- `backend/fly.toml` (#13): the committed config of the dev Fly app `lineup-dev-lb` (`-lb` = the owner's initials, only there because Fly app names are globally unique; not "load balancer"). Region `ams` (EU, compliance G10; the Supabase project is in `eu-west-1` and Fly has no Dublin), scale to zero (`auto_stop_machines = "stop"`, `min_machines_running = 0`), 1 GB `shared-cpu-1x` for LibreOffice with `PDF_MAX_CONCURRENT=1`, a `GET /health` check (liveness only, like the image's `HEALTHCHECK`). `[env]` holds only non-secret values (`ENV=production`, `CLIENT_IP_HEADER=Fly-Client-IP`, `PDF_MAX_CONCURRENT`); secrets go through `fly secrets set`, and `tests/test_fly_config.py` fails on a region outside the EU or a secret-looking key in `[env]`. Deploy with `cd backend && fly deploy --ha=false` (the build context is `backend/`). `--ha=false` is required: Fly otherwise creates two machines on the first deploy, and the in-memory rate limiter (`lineup/security/rate_limit.py`) is only correct with one. The CD workflow (`.github/workflows/deploy-dev.yml`, #8) passes it too, and `tests/test_deploy_workflow.py` fails if it stops. `fly.toml` is in `.dockerignore`.
- `CMD` runs `uvicorn` straight from `/app/.venv/bin` (on `PATH`): no `uv` at runtime, so no writable cache/`HOME` needed for it. It passes `--no-access-log`: invite codes are URL path segments (`/invitations/<code>`) and the access log would print them, with the client IP, into the platform logs (`tests/test_container_config.py` guards it; `task serve` is local only and keeps its log).
- `compose.yml` (repo root): single `api` service using the pre-built `lineup` image (not `build:`), with `cap_drop: [ALL]` and `no-new-privileges` (LibreOffice needs neither); the image's `HEALTHCHECK` is inherited, and `task test-e2e` starts it with `docker compose up -d --wait`. It gets its settings from `env_file: backend/.env` with `required: false` (Compose >= 2.24) — compose's own `.env` interpolation only looks next to `compose.yml`, so it would silently stop seeing `backend/.env`. With no `backend/.env` the container falls back to its in-container SQLite default.
- `task build` / `task rebuild` builds the image; `task up` / `task down` starts/stops it; containers can be monitored using `lazydocker`
- CI's `e2e` job scans the built `lineup:latest` image with `aquasecurity/trivy-action` (severity `CRITICAL,HIGH`) after `task test-e2e` runs — report-only (`exit-code: "0"`, never fails the build), since the LibreOffice + apt package surface has more CVEs than can realistically be kept at zero. Results go to the job log (table format) and the repo's Security → Code scanning tab (SARIF upload via `github/codeql-action/upload-sarif`).

## Day to day

- `compose.e2e.yml` (repo root) is layered on top of `compose.yml` by `task test-e2e` only (`-f compose.yml -f compose.e2e.yml`). `POST /lineups` needs a token, so it sets `SUPABASE_URL=http://localhost:9999` on `api` and adds a `jwks` sidecar (same `lineup` image, `network_mode: "service:api"`, `python -m http.server` on `127.0.0.1:9999`) serving the public key that `scripts/e2e_keys.py` wrote to the git-ignored `.e2e-auth/public`. Uvicorn's default proxy-header handling is left alone: behind Fly the client IP comes from `CLIENT_IP_HEADER=Fly-Client-IP`, not from trusting `X-Forwarded-For`.
- `compose.yml` uses `image: lineup`, not `build:` — so `task build`/`task rebuild` is always needed before `task up`
- To fully reset: `task down` → `docker rmi lineup` → `docker image prune` → `task rebuild` → `task up`
