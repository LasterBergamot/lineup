# Frontend (`frontend/`)

React 19 + TypeScript + Vite (pnpm; the version is pinned by `packageManager` in `package.json`), Tailwind v4 with the Polaris tokens as CSS variables in `src/index.css` (square corners, light + dark; the `dark` class on `<html>` is set before first paint by `public/theme-init.js`, a separate file rather than inline so a strict CSP (#97) stays possible), shadcn-style components in `src/components/ui/` (`cn()` from `src/lib/utils.ts`; semantic tokens only, never raw hex), React Router (`BrowserRouter`/`Routes` in `src/app.tsx`), react-i18next (Hungarian default, English selectable), TanStack Query, Vitest + Testing Library (`src/**/*.test.ts(x)`, setup in `src/test/setup.ts`).

- **Generated API client**: `src/api/openapi.json` is dumped offline from the FastAPI app (`scripts/dump_openapi.py`, no server) and `src/api/schema.d.ts` is generated from it by openapi-typescript; `src/api/client.ts` wraps it in `openapi-fetch`. Never edit the generated files; after any backend endpoint/schema change run `task fe:api` and commit the result, otherwise CI's `task fe:api:check` fails.
- **API base URL**: `VITE_API_URL` if set, else the same-origin `/api`, which the Vite dev server proxies to `VITE_DEV_API_TARGET` (default `http://localhost:8000`) with the prefix stripped, so local dev needs no CORS. `VITE_*` values are public: no secrets in `frontend/.env*` (ignored by the repo except `.env.example`).
- **Cold starts (PLAN.md §5)**: `BackendStatusProvider` (`src/backend-status/`, mounted outermost in `app.tsx`) polls `GET /health` on load (`unknown -> waking after 1.5 s -> ready | down`, then one `?db=true` check for `db-paused`) and `BackendStatusBanner` (inside `AppShell`) shows the message; the wake-up text sits behind `VITE_COLD_START_NOTICE` (on unless `"false"`). `createQueryClient()` retries only transient failures (`isTransient`: status 0 or 502/503/504) with 1-2-4-8 s backoff, never 4xx and never mutations. Use `request()` from `src/api/errors.ts` around every `openapi-fetch` call so failures become `ApiError`, `describeError()` for user-facing text (never show or log server error text), `QueryBoundary` + `Skeleton` for each data region and `<Button loading>` for mutations. Timeouts: `DEFAULT_TIMEOUT_MS` 60 s, `PDF_TIMEOUT_MS` 130 s (above the backend's 120 s LibreOffice limit).
- **Lineup form (`src/features/lineup/`)**: `schema.ts` (Zod, mirrors the backend's `CleanStr*`/`LineupRequest` limits — keep them in sync when the API's limits change), `generate.ts` (`generateLineup()`: `POST /lineups` through `generateApi`, the 130 s client, `parseAs: "blob"`, file name from `Content-Disposition`), `download.ts` (`saveFile()`, header parsing), `lineup-form.tsx` (React Hook Form + `useMutation`; 422s are mapped onto fields with `fieldErrors()`; PDF-wait notice after 5 s via `useAfterDelay`). Form values hold players' personal data: keep them in component state only — no localStorage/sessionStorage drafts, no logging.
- **Sign-in and teams (`src/auth/`, `src/features/teams/`)**: `@supabase/supabase-js` is used for sign-in only (D6). `getSupabase()` (`auth/supabase.ts`) creates the client lazily from `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`, checked by `readSupabaseConfig()` (`auth/config.ts`: https except localhost, and a `sb_secret_...` / `service_role` key is **refused** because `VITE_*` is public); PKCE flow, session in localStorage (strictly necessary; the privacy notice must disclose it, #94/#97; the theme `lineup-theme` and the language `lineup-lang` are the only other storage entries). `AuthProvider` (`auth/provider.tsx`, inside `QueryClientProvider`) mirrors `onAuthStateChange` into `useAuth()` (`loading | signed-out | signed-in | unconfigured`), empties the query cache whenever nobody is signed in and signs out on a 401. `createAuthMiddleware()` (`api/auth-middleware.ts`, attached to `api` and `generateApi`) adds `Authorization: Bearer` to every call except `/health` and reports a 401 that carried a token through `auth/events.ts`; never log or store the token anywhere else. `RequireAuth` guards the routes (redirect to `/sign-in`; the wanted path is kept in `sessionStorage` via `safeReturnPath()`, which accepts only same-site paths: it is the open-redirect guard, keep it that way). `TeamsProvider` loads `GET /teams` once (query key includes the user id); `TeamGate` shows `Onboarding` (create a team, or paste an invite link into `InviteLinkForm`) when the user has none. An API 503 shows the retry box, never a sign-in loop. Tests use a fake auth client and a mocked `features/teams/api` (`src/test/auth.tsx`); nothing touches the network. `scripts/smoke_auth.py` can stand in for Supabase Auth for a local run (see `documentation/Auth-Setup.md`).
- **Members and invitations (`src/features/members/`, `src/features/invitations/`, #189)**: the **Team** page (`/members`, 4th nav item) shows `MembersList` and, for an owner only, `InvitePanel`. Members are shown as `You` / `Member N` (the API returns ids and roles, no names): never render a user id. Destructive actions use `ConfirmButton` (a two-step confirm, no modal); the server decides what is allowed, so a 403/404/409 is mapped to a message (`describeError`, and `members.lastOwner` for the 409 on leaving as the only owner). A new invite link (`code`/`url`) exists only in the response: `InvitePanel` keeps it in component state, never in storage, a query key or a log. `/join/:code` (`pages/join-page.tsx`) is outside `RequireAuth` on purpose: the preview (`GET /invitations/{code}`) is public, so the visitor sees "Join <team>?" before signing in. Signed out, the button calls `rememberReturnPath('/join/<code>')` and starts Google sign-in; the sign-in page forwards back, and the page clears that `sessionStorage` entry the moment the user is signed in (also after joining, and `signOut` clears it), then a **second, explicit button** calls `POST /invitations/{code}/accept` (opening a link must never join anyone by itself) and navigates with `replace` so the code is not left in the history. The preview query waits for `status !== "loading"`: `AuthProvider` empties the query cache when it finds nobody signed in, which would otherwise discard the request and send it twice (double-counting the invite rate limit). 404/422 mean "unknown link", 410 "expired or revoked"; anything else gets the retry box. `InviteLinkForm` takes a pasted link or bare code, keeps only the code (`inviteCodeFromInput`) and navigates to `/join/<code>`: never to the pasted origin. API timestamps go through `lib/format-date.ts` (a value without a zone is UTC).
- **Roster (`src/pages/roster-page.tsx`, `src/features/players/`, `src/features/directory/`, `src/features/teams/team-settings-card.tsx`, #197)**: the Roster page stacks three cards for the current team. `PlayersCard` lists the team's players (`listPlayers()` reads every page of `GET /players?team_id=`; key `playersKey(userId, teamId)`), adds, edits in place and deletes them (`ConfirmButton`); **every member** may do all of it, the team is the workspace, so nothing is gated on role. Only name and NSSZ number exist (data minimisation, G4): never add a field without updating `documentation/Privacy-and-Security.md`. Deleting a player does not touch already saved lineups (they keep a frozen copy), and a hint under the list says so. `TeamSettingsCard` (rename + "listed in the opponent directory" through `updateTeam()` -> `PUT /teams/{id}`) is mounted for owners only and returns `null` for anyone else; the server answers 403 regardless. `DirectoryCard` searches `GET /teams/pool` with `useDebouncedValue` (300 ms), shows team **names only**, keeps the previous results while typing and keeps the search term in component state and the in-memory query key only (no URL, storage or log). Player forms and search terms are personal data in transit: no storage, no logging.
- **Lineup creator and preview (`src/features/creator/`, `src/features/preview/`, #203)**: `/` is the creator (`LineupPage` loads the roster, then `LineupCreator`); the old `LineupForm` stays behind the "Quick sheet" toggle. `schema.ts` (Zod) mirrors `SavedLineupCreate` (a slot is a roster `playerId` or typed-in text; `name`/`nssz_number` always hold what is printed), `resolve.ts` turns the values into the two requests (`toLineupRequest` for the stateless preview, `toSavedLineupRequest` for saving: roster picks and a listed opponent go as ids, the API wants exactly one of id/text per field), `valuesFromSaved()` starts "Clone to new match" and `formPath()` maps a 422 path onto a form field. The Saved page passes only `state: { cloneFromId }`; `LineupPage` fetches the lineup (`getSavedLineup`), because the lineup holds names and NSSZ numbers and history state is browser storage. `opponent/` is the combobox (native `<input list>` + `<datalist>`; the typed text becomes `source_opponent_id` only when it equals a listed team's name) and `recentOpponentsKey` must be invalidated after a save. The preview is a PDF `Blob` in a mutation with `gcTime: 0`, drawn on canvases by `PdfViewer`: pdf.js is a lazy chunk (`pdfjs.ts`) with its worker bundled via `?url` (same origin: no CDN, and a strict CSP #97 needs only `worker-src 'self'`); never give the blob a URL or store it. The staff fields other than the coach are optional (blank is omitted from the request). Query keys under `["saved", ...]` are refreshed by the creator after saving. In tests never write `beforeEach(() => mock.mockReset())`: Vitest runs a function returned from a hook as its teardown.
- **i18n (`src/i18n/`, #155)**: **every user-facing string goes through `t()`**; the texts live in `src/i18n/locales/hu.json` + `en.json` (same keys in both, a test enforces it; keys are type-checked against `hu.json`), and `eslint-plugin-i18next`'s `no-literal-string` (JSX text + `placeholder`/`aria-label`/`alt`/`title`, not tests or `components/ui/`) fails `fe:lint` otherwise. Wrap sample data and proper nouns (`Lineup`) in a constant. `src/i18n/index.ts` bundles both files (no HTTP backend, no third-party request), reads the language only from localStorage `lineup-lang` (never `Accept-Language`; Hungarian when unset) and `setLanguage()` is the only writer (a strictly necessary preference, to be disclosed in the #94 notice; store nothing else about the visitor). A `languageChanged` listener keeps `<html lang>` in sync. Zod schemas stay module-level constants and emit **error keys** (`errorKey("validation.required", { field: "fields.match" })`, `lib/clean-text.ts`); `Field` translates them at render with `translateError()`, so shown errors re-translate on a switch; `describeError(error, t)` and the nav `labelKey` are translated the same way. Server 422 sentences (`fieldErrors()`) and `AuthConfigError` stay English (known gap). Cap colour values (`Fehér`/`Kék`) go to the API, only their labels are translated. Tests start in English (`src/test/setup.ts` calls `changeLanguage("en")`, which does not write storage); import `i18n` and switch explicitly to test Hungarian. The `.docx` template is not translated. `public/theme-init.js` stays a separate file.
- **Hosting (Cloudflare Pages, #175)**: `public/_headers` is copied into `dist` and sets the baseline security headers (HSTS, `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `frame-ancestors 'none'`; the strict CSP is #97). `src/security-headers.test.ts` checks it. Pages serves `index.html` for unknown paths only while there is no top-level `public/404.html`, so never add one (deep links such as `/join/:code` depend on it). Only public `VITE_*` values go in the Pages settings; keep Cloudflare Web Analytics off (G14). PR previews cannot sign in or call the API (their origin is not in `CORS_ORIGINS`, which is exact-match on purpose). Setup: `documentation/Pages-Setup.md`.
- **Fonts and third parties**: Google Sans Flex is self-hosted through Fontsource; the app must not request any third-party origin (#97, GDPR G14).
- **Coverage (`task fe:coverage`, #199)**: `vite.config.ts` (`test.coverage`) counts every file under `src/` except tests, `src/test/`, the generated `src/api/schema.d.ts`, `vite-env.d.ts` and the bootstrap `src/main.tsx`, and fails the run below **100 %** statements, branches, functions and lines, like the backend. A new branch without a test fails CI: write the test, or delete the code if it is unreachable. Avoid `v8 ignore` comments; if one is truly needed, state the reason next to it. Guards that the app can never reach through its own routes (e.g. `if (!current) return null` behind `TeamGate`, a context hook used outside its provider) are tested by rendering the component or hook directly. `fe:test` stays the fast loop without coverage.
- **TypeScript is pinned to 6.0 (`~6.0.3`)**: typescript-eslint doesn't support 7.x yet; lift the pin when it does.
- CI's `Frontend` job (in `ci.yml`, no path filter so it reports on every PR) runs `task fe:install`, `fe:lint`, `fe:typecheck`, `fe:coverage` (the Vitest suite plus a v8 coverage report), `fe:build`, `fe:api:check` and a report-only `pnpm audit --prod`. It is a required check in branch protection on `develop` and `main`. Dependabot has an `npm` entry for `/frontend` (minor/patch grouped).
