# Backend: test conventions

Paths below are relative to `backend/` (run pytest from there — `task test` does).

- `pyproject.toml` enforces `fail_under = 100`
- Every new module needs a corresponding `tests/test_<module>.py`
- Any code that calls LibreOffice must mock `PdfConverter.convert` — it is not available locally. `tests/test_pdf_converter.py` mocks `subprocess.Popen` (and `shutil.which`); its one real-process test uses a fake `libreoffice` shell script that forks a child, to prove the group kill reaches it (Linux `/proc` only)
- Tests for API endpoints that trigger PDF conversion use an `autouse` fixture in `test_api.py` (and in `TestGenerateFromSavedLineup` in `test_saved_lineups.py`) that patches `PdfConverter.convert`. To force a rendering failure, patch `lineup.api.file_response.WaterPoloLineupCreator` — that's where both endpoints construct it now
- `tests/test_pdf_conversion_e2e.py` is the exception: it drives the **real** conversion against the running container. `POST /lineups` needs a token, so `task test-e2e` first runs `scripts/e2e_keys.py` (fresh ES256 key into the git-ignored `.e2e-auth/`) and starts the container with `compose.e2e.yml`, whose `jwks` sidecar serves the public key on `localhost:9999` inside the API's network namespace (`SUPABASE_URL=http://localhost:9999`); the test signs its token with `private.pem`. It runs as its own Compose project on host port 8001 (`LINEUP_API_URL`), so a running `task up` is unaffected. It is marked `e2e` and excluded from `task test` by `addopts = "-m 'not e2e'"` (so it never affects coverage); run it via `task test-e2e`. It talks to the API over HTTP (stdlib `urllib`) and validates layout with `pdfplumber` — asserting a single page, expected text, and that word widths/positions match `expected-rajtlista.pdf`. It does **not** pixel-diff (the reference uses real Calibri, the container uses metric-compatible Carlito).
- `tests/conftest.py` has an autouse fixture resetting the rate limiters between tests, and the sync `client` fixture is signed in as `current_user` (override of `get_current_user_id`; `POST /lineups` needs a token). For an anonymous call build `TestClient(app)` yourself. `tests/test_security.py` covers lineup/security (headers, body cap, limiter, 429 on both generate endpoints, docs flag, production-config failures); lower a limit with `monkeypatch.setattr(LIMITERS["generate:user"], "limit", 2)`.
- DB tests use the `async_client` fixture (`tests/conftest.py`) — a fresh in-memory SQLite DB per test, with `get_session` overridden to open a **new session per request** (like production; a shared session hid stale rows after deletes, #59) and `get_current_user_id` overridden to the `current_user` fixture's id (assign `current_user.id = uuid.uuid4()` mid-test to act as a second user). `tests/test_tenant_isolation.py` uses that to prove one user can't reach another's rows (404) and teammates share theirs (`TeamMember` rows added directly via `tests/helpers.py:join_team`; joining through a link is covered in `tests/test_invitations.py`, members and ownership in `tests/test_team_members.py`); the repository tests also call the user-scoped functions directly with real ids. `tests/helpers.py` (`ensure_team`, `create_player`) gives tests the team that players and lineups must live in. `db_session` is a *separate* session on the same engine for arranging or asserting rows directly: `expire_all()` it before reading something an API call changed.
- `tests/test_auth_dependencies.py` also walks every route in `app.openapi()` and expects 401 without a token, except `PUBLIC_ROUTES` (add a route there only on purpose, with a rate limit). It reads the OpenAPI document, not `app.routes`: recent FastAPI versions keep `_IncludedRouter` wrappers there and the old walk silently collected nothing (`test_the_route_walk_sees_the_api` guards that). Tests that lower a limiter use `monkeypatch.setattr(LIMITERS[...], "limit", n)` so the value is restored.
- `tests/test_auth_dependencies.py` tests the real token check with throw-away keys generated in the test (ES256 and RS256), a fake JWKS fetch function and a fake clock: no network, no Supabase. Keep it that way.
- `[tool.coverage.run]` in `pyproject.toml` sets `concurrency = ["greenlet", "thread"]` — required for accurate coverage of any code that calls SQLAlchemy's async ORM. Don't remove it; without it, coverage under-reports on lines following an `await session.commit()`/`.refresh()`/etc. even though they actually ran.
- `tests/test_postgres_migrations.py` asserts RLS/role/grant behaviour against a real Postgres; it is **skipped** unless `POSTGRES_TEST_URL` is set (a throwaway, empty DB — CI's `Migrations (Postgres)` job sets it; locally run a `postgres:17` container). `tests/test_app_role.py` covers the password/`.env` rewriting and the typed-`yes` confirmation with a fake engine (no DB; `_files()` passes `--yes`, the confirmation tests drop it and patch `builtins.input`).
- `tests/test_app.py` covers both branches of `app.py`'s Sentry init (`SENTRY_DSN` set/unset) by mocking `sentry_sdk.init` and `importlib.reload`-ing the `app` module under each env state. Every new env var read at import time must be added to its `teardown_module` (it pops them and reloads), and tests that need an env state use the `reload_app` / `reload_with_env` fixtures (docs on/off, production startup failure, CORS + 413). Safe to reload freely: `tests/conftest.py` imports `app` once at collection time and keeps its own reference, so a later reload elsewhere doesn't retroactively affect the `client`/`async_client` fixtures. Note `[tool.coverage.run] source = ["lineup"]` doesn't include `app.py`, so this file's coverage isn't actually gated by `fail_under = 100` — the tests exist for correctness, not the coverage requirement.
