# Lineup API

API for creating and managing sports team lineups with PDF export functionality.

## Overview

This project provides a REST API for creating lineups for sports teams (initially focused on water polo in Hungarian leagues) and exporting them as printable PDF documents.

## Setup

### Prerequisites

- Python 3.11 or higher
- Poetry (install via `pip install poetry`)

### Installation

1. Configure Poetry to create virtual environments in the project directory (if not already configured):
   ```bash
   poetry config virtualenvs.in-project true
   ```

2. Install dependencies and create the virtual environment:
   ```bash
   poetry install
   ```
   This will create a `.venv` directory in the project root with all dependencies installed.

### Virtual Environment

The project uses Poetry to manage a virtual environment located in the `.venv` directory at the project root.

#### Activating the Virtual Environment

**If the virtual environment already exists** (`.venv` directory is present):

**On Windows (PowerShell):**
```powershell
.\.venv\Scripts\Activate.ps1
```

**On Windows (Command Prompt):**
```cmd
.\.venv\Scripts\activate.bat
```

**On Linux/macOS:**
```bash
source .venv/bin/activate
```

**Using Poetry (works on all platforms):**
```bash
poetry shell
```

#### Setting Up the Virtual Environment

If the `.venv` directory doesn't exist or you need to recreate it:

1. Ensure Poetry is configured to create venvs in-project:
   ```bash
   poetry config virtualenvs.in-project true
   ```

2. Install dependencies (this will create the virtual environment):
   ```bash
   poetry install
   ```

#### Running Commands Without Activating

You can also run commands directly using Poetry without activating the virtual environment:
```bash
poetry run pytest
poetry run black .
poetry run flask run
```

#### Deactivating the Virtual Environment

If you activated it manually (not using `poetry shell`), simply run:
```bash
deactivate
```

If you used `poetry shell`, exit the shell:
```bash
exit
```

## Project Files

### `pyproject.toml`

The `pyproject.toml` file is the main configuration file for the project. It serves multiple purposes:

- **Project metadata**: Defines the project name, version, description, and authors
- **Dependency management**: Lists all production and development dependencies with their version constraints
- **Build system configuration**: Specifies how the project should be built and packaged
- **Tool configurations**: Contains settings for various development tools:
  - `black`: Code formatter configuration
  - `coverage`: Code coverage settings
  - `pytest`: Test runner configuration
  - `mypy`: Type checking configuration

This file is the single source of truth for project dependencies and should be committed to version control. When you add or remove dependencies, you modify this file and run `poetry install` or `poetry add <package>`.

### `poetry.lock`

The `poetry.lock` file is automatically generated by Poetry and contains the exact versions of all dependencies (including transitive dependencies) that were installed. This file ensures:

- **Reproducible builds**: Everyone working on the project gets the exact same dependency versions
- **Consistent environments**: Development, staging, and production environments use identical dependency versions
- **Security**: Locked versions prevent unexpected updates that might introduce vulnerabilities

**Important**: The `poetry.lock` file should be committed to version control for applications (like this project) to ensure all team members and deployment environments use the same dependency versions. Poetry will automatically update this file when you run `poetry install`, `poetry add`, or `poetry update`.
